# Local RAG Document Q&A

A local Retrieval-Augmented Generation (RAG) system for answering questions from documents using **LangChain, ChromaDB, SentenceTransformers, Ollama, and Streamlit**.

The application retrieves relevant document chunks and provides them to a locally running Ollama model so responses are grounded in the supplied documents rather than relying on outside knowledge.

## Features

- Load PDF and TXT documents
- Recursive text chunking with overlap
- Preserve source and PDF page metadata
- Generate local embeddings with SentenceTransformers
- Store and retrieve vectors using ChromaDB
- Retrieve top-k relevant document chunks
- Generate grounded answers with Ollama
- Return source filenames and page numbers
- Refuse unsupported questions when the documents do not contain the answer
- CLI and Streamlit interfaces

## Architecture

```text
Documents (PDF / TXT)
        ↓
LangChain Document Loaders
        ↓
Recursive Text Chunking
        ↓
SentenceTransformer Embeddings
        ↓
ChromaDB
        ↓
Semantic Retrieval
        ↓
Relevant Document Context
        ↓
Prompt + User Question
        ↓
Ollama
        ↓
Grounded Answer + Sources
```

## Setup

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/Scripts/activate
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

Install Ollama separately and make sure the configured model is available:

```bash
ollama pull llama3.2
```

On the first run, the SentenceTransformer embedding model is downloaded from the Hugging Face Hub and then cached locally.

## Configuration

Copy `.env.example` to `.env`.

```env
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2

EMBEDDING_MODEL=sentence-transformers/all-MiniLM-L6-v2

DOCUMENTS_DIR=documents
CHROMA_DIR=storage/chroma
CHROMA_COLLECTION=local_rag_documents

CHUNK_SIZE=500
CHUNK_OVERLAP=50

TOP_K=4
```

## Build the Knowledge Base

Place PDF or TXT files inside `documents/`, then run:

```bash
python main.py ingest
```

This loads the documents, splits them into overlapping chunks, generates embeddings, and stores the resulting vectors and metadata in ChromaDB.

## Ask Questions from the CLI

```bash
python main.py ask "Which vector database does this system use?"
```

Example:

```text
Answer
------------------------------------------------------------
The vector database used in this system is ChromaDB.

Sources
------------------------------------------------------------
- rag_sample_knowledge_base.pdf, page 2
```

If the supplied documents do not support an answer, the model is instructed to respond:

```text
I couldn't find that information in the provided documents.
```

## Streamlit UI

Run:

```bash
streamlit run app.py --server.fileWatcherType none
```

The interface allows you to:

- build/rebuild the document knowledge base,
- ask document-grounded questions,
- view source filenames and PDF pages,
- inspect the retrieved context used for generation.

**Python · LangChain · ChromaDB · SentenceTransformers · Ollama · Streamlit**

## How Grounding Works

The language model is not asked to answer the question directly.

The system first retrieves relevant chunks from ChromaDB and injects them into the prompt as context. The prompt instructs Ollama to answer only from that context and to report when the requested information is unavailable.

Source references are constructed from retrieved document metadata rather than generated by the language model.

## Notes

- The same embedding model must be used for document indexing and query embedding.
- ChromaDB storage is generated locally and is excluded from Git.
- `.env` is excluded from Git; `.env.example` contains the required configuration.
- Rebuilding the knowledge base recreates the ChromaDB collection from the current documents.
