# Local RAG Document Q&A

A local Retrieval-Augmented Generation (RAG) system for answering questions from documents using **LangChain, ChromaDB, SentenceTransformers, Ollama, and Streamlit**.

The application retrieves relevant document chunks and provides them to a locally running Ollama model so responses are grounded in the supplied documents rather than relying on outside knowledge.

## Features

- Load PDF and TXT documents
- Recursive text chunking with overlap
- Preserve source and PDF page metadata
- Generate local embeddings with SentenceTransformers
- Store and retrieve vectors using ChromaDB
- Retrieve top-k relevant document chunks
- Generate grounded answers with Ollama
- Return source filenames and page numbers
- Handle questions unsupported by the retrieved document context
- CLI and Streamlit interfaces

## Architecture

```text
Documents (PDF / TXT)
        ↓
LangChain Document Loaders
        ↓
Recursive Text Chunking
        ↓
SentenceTransformer Embeddings
        ↓
ChromaDB
        ↓
Semantic Retrieval
        ↓
Relevant Document Context
        ↓
Prompt + User Question
        ↓
Ollama
        ↓
Grounded Answer + Sources
```

## Setup

Create a virtual environment:

```bash
python -m venv .venv
```

### Windows Git Bash

```bash
source .venv/Scripts/activate
```

### macOS / Linux

```bash
source .venv/bin/activate
```

Install the tested project dependencies:

```bash
python -m pip install -r requirements.txt
```

## Ollama

Install Ollama separately and make sure the configured model is available:

```bash
ollama pull llama3.2
```

Ollama must be running before asking questions.

You can confirm the local Ollama server is available with:

```bash
ollama list
```

On the first run, the SentenceTransformer embedding model is downloaded from the Hugging Face Hub and cached locally.

## Configuration

Create `.env` from `.env.example`.

```env
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2

EMBEDDING_MODEL=sentence-transformers/all-MiniLM-L6-v2

DOCUMENTS_DIR=documents
CHROMA_DIR=storage/chroma
CHROMA_COLLECTION=local_rag_documents

CHUNK_SIZE=500
CHUNK_OVERLAP=50

TOP_K=4
```

## Build the Knowledge Base

Place PDF or TXT files inside `documents/`, then run:

```bash
python main.py ingest
```

The ingestion pipeline:

```text
Documents
   ↓
Load + preserve metadata
   ↓
Recursive chunking
   ↓
Generate embeddings
   ↓
Store chunks and metadata in ChromaDB
```

Re-running ingestion rebuilds the local ChromaDB collection from the documents currently present in the directory.

## Ask Questions from the CLI

```bash
python main.py ask "Which vector database does this system use?"
```

Example:

```text
Answer
------------------------------------------------------------
The vector database used in this system is ChromaDB.

Sources
------------------------------------------------------------
- rag_sample_knowledge_base.pdf, page 2
- rag_sample_knowledge_base.pdf, page 1
```

Source references come from retrieved document metadata rather than being generated by the language model.

For a question that is not supported by the supplied documents, the system is instructed to respond:

```text
I couldn't find that information in the provided documents.
```

## Streamlit UI

Run:

```bash
streamlit run app.py --server.fileWatcherType none
```

The interface supports:

- building or rebuilding the document knowledge base,
- asking document-grounded questions,
- displaying source filenames and PDF pages,
- inspecting retrieved document chunks.

## How RAG Works

The language model is not asked to answer the question directly.

When a question is submitted:

1. The question is embedded using the same embedding model used during indexing.
2. ChromaDB retrieves the top relevant document chunks.
3. Retrieved chunks are formatted as document context.
4. The context and question are inserted into a grounded prompt.
5. Ollama generates the response using the supplied context.
6. Source references are built from the metadata of the retrieved chunks.

This separates **retrieval** from **generation** and keeps source reporting independent of the language model.

## Known Limitations

- Sources represent the unique pages present among the retrieved top-k chunks. A secondary page may therefore appear alongside the page containing the strongest supporting passage.
- Retrieval is based on semantic similarity and a fixed `TOP_K`; this implementation does not include reranking or hybrid retrieval.
- The system is designed for text-based PDF and TXT documents. Scanned PDFs requiring OCR are not handled by the current ingestion pipeline.
